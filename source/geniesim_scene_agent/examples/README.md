# Task examples

This library contains **110 task implementations** and **1,116 scene
instances**. There are 10 scenes for each of 109 tasks, plus 26 A-Z writing
scenes. Browse the [task family tables](../skills/find-example/references/index.md)
for descriptions, interfaces, configuration classes, and scene keywords.

## Directory layout

```text
examples/
  bind_assets.py
  validate.py
  assets -> configured external assets directory
  tasks/<task_name>/
    data_gen.py
    task_info.json
    object_urls.json
    manifest.json
    README.md                      # interface tags and scene links
    LLM_RESULT_*.py                 # optional DSL recipe
    <scene_instance>/
      scene.usda
      scene_info.json
```

Some examples include task guides, generation metadata, validation reports,
or renders. Each task's manifest lists its current files and scene instances
with hashes for integrity checks.

Each task's README lists RobotAPI calls, client calls, configuration classes,
scene/action tags, and all instances. These are also stored as `interface_tags`,
`configuration_tags`, and `scene_action_tags` in its existing manifest.
Tags describe static code observations, not physical success or branch coverage.
Refresh them with `python3 -m scene_agent_scene.find_example tag`.

## Find references before writing data_gen.py

Use the [find-example skill](../skills/find-example/SKILL.md) to compare several
implementations by task flow, scene type, API usage, and object keywords:

```bash
python3 -m scene_agent_scene.find_example search "open microwave door" --limit 5
python3 -m scene_agent_scene.find_example search "hold bowl place fruit" --tag held_container
```

Read each selected `data_gen.py`, `task_info.json`, `scene_info.json`, and
`scene.usda` together. Review an accompanying DSL recipe when layout logic
affects the task. Match object roles and literal keywords before adapting the
code. The [RobotAPI quick reference](../skills/geniesim-scene-generation/references/robot_api.md)
and [complete parameter reference](../skills/geniesim-task-orchestration/references/robot_api_reference.md)
explain interface and pose conventions. Apply
[task orchestration](../skills/geniesim-task-orchestration/SKILL.md) and
[task validation](../skills/geniesim-task-validation/SKILL.md) when adapting code.
Task execution needs a compatible
robot runtime providing the `client.llm_gen.robot_api` and
`common.base_utils.transform_utils` modules.

For scene layout search:

```bash
python3 -m scene_agent_scene.similar "fruit on a shelf" --task-root examples/tasks --limit 5
```

## External assets

All scenes use the single `examples/assets` link. Provide an external GenieSim
asset library and bind it from the repository root. The helper discovers the
CLI configuration, installed asset package, or relative `assets/` directory:

```bash
python3 examples/bind_assets.py
# Optional explicit override:
python3 examples/bind_assets.py --assets-root /path/to/assets
```

See [asset discovery order](../README.md#external-asset-discovery). Python tools
use the real asset directory directly; the link supports the example USD files.

The library must contain the objects, interaction annotations, and backgrounds
referenced by the selected scenes. Assets are not bundled with this repository.
The symlink is local configuration and is excluded from Git. The configured
library determines which asset versions are loaded.

## A-Z writing scenes

The [writing guide](tasks/write_uppercase_letter_with_pen_g2/write_uppercase_letter_with_pen_g2.md)
and [trajectory gallery](tasks/write_uppercase_letter_with_pen_g2/alphabet_trajectories.png)
document the shared implementation. Scene `0` specifies `target_letter: "A"`;
scene `25` specifies `target_letter: "Z"`. `data_gen.py` reads this field to
choose both the instruction and pen strokes. Invalid or missing values fail
before motion.

The writing instances share one initial physical layout. The gallery shows
the letter paths; initial workspace preview images are not bundled. New scene
designs default to foreground only unless a background is requested.

## Validate

Use a Python environment with working USD bindings:

```bash
python3 examples/validate.py
python3 examples/validate.py --output .cache/example_validation.json
```

The validator checks task/scene names, file inventory and hashes, writing
letters, Python syntax, USD layers, `/World/Objects`, and direct asset
references. Use Isaac Sim rendering and the configured robot runtime for
physical execution checks after adapting an example.
